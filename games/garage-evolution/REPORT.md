# Idle Garage Evolution (garage-evolution)
Brief: "GARAGE EVOLUTION" from publisher/ideas/2026-10-10-garage-evolution.md — an incremental restoration clicker: a wreck rolls in, you take it apart layer by layer where you touch it (mud → rust → old paint → polish → wheels → parts → engine), it drives out restored; tools and robots automate the work, the garage grows from a shed to a space hangar.
Audience / channel / kit / mechanic / theme: `general` / `crazygames` (then Playgama) / `code` (Canvas 2D) / own: scrub layers off a car with a mask, plus a tyre-bay job / own: a garage that grows (shed → workshop → service station → luxury studio → plant → space hangar).

## Friction and bugs
- `gp design --gemini` (its first real run, 2026-10-20) produced no answer in five tries: the default `gemini-2.5-pro` → 404 «no longer available to new users, use gemini-3.1-pro-preview»; `GP_DESIGN_MODEL=gemini-3.1-pro-preview` → 429 «free tier, no quota for this model»; `gemini-2.5-flash` → 404 «use gemini-3.8-flash»; `gemini-3.8-flash` → 502 «upstream request failed» twice (with the 2.4 MB video inline). In a cloud session the key is a network secret: `GEMINI_VIA_NETWORK=1` worked as documented. → `packages/cli/src/gemini.ts`: a default model new keys can use (and fall back on a 404 to the model the error names); on a free key say before the 90-s video is recorded that Pro models have no quota; maybe the File API instead of the inline video for the 502. The rest of `gp design` (the brief, the sheet, the designer agent) ran without it.
- `gp submission --full` warns «publisher/results.yaml has no stop or rejection for this game» although the stop is recorded — under `game: idle-garage-evolution`, while game.yaml's id is `garage-evolution`, so the resubmission discount isn't applied → publisher/results.yaml: the entry's `game:` should be `garage-evolution` (or match on `repo:` too).
- Asset chapters, a trap for any game with a cover hook or an async start(): a hook that depends on a later picture must not exist before it is decoded, and `gp covers` takes `body[data-cover=ready]` as «use the frame» even when a hook comes a moment later; and `gp playgama-check` reads game_ready the moment `qaDriver` exists, so an `await` in start() after `host.qa()` fails it → packages/cli/src/covers.ts: wait the full 8 s for a hook once the frame flag is up (or a `cover: 'pending'` marker); playgama-check: wait for `host.loaded` before checking game_ready.
- Asset chapters for pictures a game imports itself (1.5.1): the chapter is only reachable through game.yaml `art.assets` (gp art writes the `?gp-chapter=` imports); a game with its own import tool writes them by hand (tools/paint-cars/chapters.py) — `createAssets` takes the manifest, so it works, but `gp art import --chapter` doesn't apply. → docs/guides/art.md § 5.2: a short note «your own pictures: import them with `?gp-chapter=<n>` and pass `{ urls, chapters }`» would have saved reading chapters.ts. Two traps worth a line there: asking `ready(<later chapter>)` at boot for anything (a dev helper did) starts it before the first screen; and the cover hook must not exist before its pictures are decoded (I set it with a second `host.qa` once `ready` resolves — `CoverArt` could take an optional `ready: Promise` instead).
- `gp design`, from the designer agent who used it: (1) the brief doesn't say whether the build is frozen — I was still editing, Vite's HMR reloaded the page twice mid-session (to a player bot it looks like a jump to the title) → `gp design` could start a frozen server (`startDev(..., { frozen: true })`, as QA does) and print its URL in the brief; (2) `--check` reports the line a proposal starts on, not the failing «how» part, and its «names no block and no code» rule accepted only catalog block names or file names (a function name like `dailyCar()` failed until a file name was added); (3) «15 proposals (3 high)» counts the sections without the Top 3 — ambiguous; (4) «✗ a level shop» is a false negative: the game's own ×1/×10/MAX shop isn't a block the search sees; (5) no hooks to drive a game: `qaDriver.demo()` can't be switched off, there is no «current stage / what to touch now» hook, the designer reverse-engineered the tyre bay from the code → a documented `host.qa({ state })` for designer bots; (6) the sheet's stops come from the demo bot tapping «again» every ~25 s while the card goes on by itself — the sheet could say which cards auto-continue; (7) the brief mixes the portal numbers of 1.0–1.4 with the 1.5.0 changes without saying which build each number measured; (8) the hits' first minute can't be read from a web search of their pages.
- `host.load(defaults)` keeps only the keys a non-empty default map has (`mergeShape`): a game whose default save has a map keyed by ids (`sites: { shed: … }`) silently loses every other key on each reload — the owner lost every garage but the first. → `packages/core/src/save.ts`: say it in `host.load`'s doc in big letters, or treat a map whose values all share one shape as a record (merge each stored key against the default entry's shape); `gp validate` could warn on a non-empty object default whose keys look like ids.
- A growing set of painted pictures has no way to stay under a size budget: every picture is base64 in the one index.html, loaded before Play (1.3.5: 40 pictures, 1.5 MB gzipped, ≈ 9.3 s on the slow-phone model; ≈ 35 KB each further one) → `@gp/art/assets` could load a later chapter's images after Play (from the same file, decoded on demand) so the first-load budget counts only the first garages'.
- The model's "session ends with a goal in reach" samples one instant: with the same economy, moving the stages' attempt length 0.8 → 0.85 min flipped it from 6 % to 64 % at minute 15, and a pool change flipped it back (a sweep of 13–17 min at 0.7–0.95 gives 6–100 % in no order). → packages/core balance-model: take the best goal share over a window (e.g. session ± 1 min) or the median over it. In 1.3.1 I stopped nudging it: the model's stages are 2-minute batches with a 1-minute attempt, which keeps the goal ≥ 60 % at every instant from 13.5 to 16.5 min (a sweep of stage 1–3 × attempt 0.6–1.2 found it).
- `gp dev` once kept serving a stale data.ts after the file was rewritten (the other files reloaded); the space garages were missing until a restart → packages/cli dev: on a full page load, check mtimes of the game's own files against the transform cache.
- `gp qa --failed` refuses after a `--quick` run ("the last run was a --quick run") — re-running only the failed section of a quick run would save a full run while iterating → packages/cli qa: allow `--failed` after `--quick` (re-run the failed quick sections).
- `gp story` gives a hint (I_STORY_DEPTH) for an idle game with no `story` section even when every vehicle carries a one-line backstory; `story: { depth: none }` silences it — fine, but the hint could mention "per-item flavour text counts as none".
- `translate --check` doesn't notice a stale translation when the English source changes (the 40 vehicle subtitles were rewritten; the check stayed green with the old texts in 9 languages) → packages/cli translate: keep a hash of the English value per key in each strings file and warn when it changes.

- `gp qa` passed while a hint ran off the screen in German and Polish (the reviewer found it): the text checks sample the declared screens, and a hint lives a few seconds between them → packages/qa: while the demo bot plays the longest language, sample every visible DOM text box each second and fail one that leaves the frame or overlaps a button.
